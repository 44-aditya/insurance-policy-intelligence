# Ian Xiaohei Illustrations setup

This repository includes the English **Ian Xiaohei Illustrations** skill for
documentation and portfolio illustrations. It is an optional authoring aid for
README explanations, project write-ups, and portfolio case studies.

## Installation and use

The installable bundle is committed at
[`../.agents/skills/ian-xiaohei-illustrations/`](../.agents/skills/ian-xiaohei-illustrations/).
Clone or pull this repository, then start a new Codex session in the repository
so it discovers `.agents/skills/`. No global installation, package installation,
API key, application dependency, or build change is required. Implicit invocation
is disabled in `agents/openai.yaml`.

Invoke explicitly, for example:

```text
Use $ian-xiaohei-illustrations to plan one illustration for the README's
evaluation-first explanation. Use only the public README text; do not generate yet.
```

```text
Use $ian-xiaohei-illustrations to generate one illustration for my portfolio
case study explaining why retrieval evaluation comes before optimization.
```

Planning needs no image tool. Generation and editing require the host's built-in
`image_gen` capability; installing this bundle does not provide that capability.
If it is unavailable, provide a shot list and prompts and report that images were
not generated. Generation defaults to three images if no count is supplied;
request one explicitly for a small task. Generation and retries may incur image
tool costs; no images are generated by installation or repository tests.

The skill provides `plan_only`, `generate`, `edit`, and `save` modes. Read its
[`SKILL.md`](../.agents/skills/ian-xiaohei-illustrations/SKILL.md) and the selected
mode's references before use. Generated PNGs default to
`assets/<article-slug>-illustrations/` in the repository root, outside the installed
bundle. Request `docs/assets/<article-slug>-illustrations/` explicitly if desired.
Use sequential names and version suffixes rather than overwriting files. Review
the visual QA manifest and add useful alt text when embedding an image in docs.

## Repository scope

All modes are limited to documentation and portfolio illustrations, on explicit
skill invocation or an Ian/Xiaohei style request. Application UI, policy answers,
authoritative corpus files, evaluation assets/results, and experimental evidence
are outside scope, including when the style is explicitly requested. This rule
is recorded in repository `AGENTS.md`, skill frontmatter, and the skill's local
scope section. Use only public or sanitized project text with image tools.
Explanatory metaphors must not invent policy facts, metrics, or capabilities.

## Inspection and local changes

Before installation, reviewed `SKILL.md`, all five references, `agents/openai.yaml`,
the license and notice, bundle inventory, and upstream `scripts/validate-skill.mjs`.
The bundle contains no executable scripts. The upstream validator uses Node's
standard library for filesystem, instruction, fixture, link, hash, and PNG checks;
it performs no network calls or image generation. It passed on the pinned checkout.
Its source repository fixtures and package metadata are required for that check,
so the validator, npm project, top-level examples, evaluations, and other upstream
development files are not installed here.

Local changes are limited to the skill's discovery description and added scope
section, agent description/default prompt and disabled implicit invocation.
References, VERSION, and all eight PNGs are unchanged. The upstream root LICENSE
and NOTICE are added beside the installed skill to preserve redistribution notices.

## Updating and verification

Fetch upstream into a temporary directory outside this repository; check out a
specific commit, inspect instructions/references/scripts/notices again, and run
`node scripts/validate-skill.mjs` there. Copy only `ian-xiaohei-illustrations/` and
the applicable notices. Reapply and review the documented local restrictions;
do not restore broad triggers or implicit invocation. Update the recorded commit
and version in this document. Keep generated project illustrations separate.

For this installation, verification checks the complete 16-file upstream bundle
inventory, unchanged-file hashes, verbatim notices, five reference paths, eight
PNG signatures/dimensions, explicit invocation policy, and local scope rules.
`git diff --check` checks whitespace. These are installation checks; live image
quality and model adherence to scope are not measured by static validation.
